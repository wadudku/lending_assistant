**In short:** A control where one person prepares an action and a second, different person approves it before it takes effect.

## Plain meaning

The BRD defines maker-checker as dual control: one user initiates an action, and a second and different user approves it (BRD 1.5).

## Example

Rahim asks for a penalty waiver. A loan officer (the maker) records it. A branch manager (the checker) approves it. The same person cannot do both steps.

## Why it matters here

BR-GOV-008 says controlled financial changes, including waiver, write-off and corrective posting, need maker-checker approval. In the test, Frappe Lending had no workflow on Loan Repayment, Loan Write Off or Loan Balance Adjustment. See `decision.waiver`.
