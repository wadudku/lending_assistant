**In short:** The configuration screen shows the rate in practical terms as well as a percentage, such as how many applications it would have selected from the partner's latest batch.

## What the rule says

BR-LOS-136 (Should, BRD 6.5, PDF page 36) says the configuration screen expresses the rate in operational terms as well as a percentage, for example how many applications the rate would have selected from the partner's most recent batch, so that the person setting it understands the review workload being created. This is a Should requirement. This is an origination rule (the LOS side of the BRD), not a servicing rule.

## Why the bank wants it

The BRD gives the reason in the row itself: so the person setting the rate understands the review workload it creates (PDF page 36).

## Example

While setting 12% for Partner A, the screen says: “On the latest batch of 400 applications this rate would have selected 48.” The person sees the workload before saving.

## Terms to know

- **Operational terms:** plain workload figures, such as a count of cases.
- **Workload:** the amount of review work for staff.
- **Most recent batch:** the latest group of applications from the partner.
- **Should:** a requirement with priority Should, not Must.
